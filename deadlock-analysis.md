# Аналіз дедлоку (Частина 2)

## Код, що аналізується

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var wg sync.WaitGroup
	ch := make(chan int) // небуферизований канал

	wg.Add(1)
	go func() {
		// симуляція важкої роботи
		ch <- 42
		wg.Done()
	}()

	wg.Wait()
	fmt.Println(<-ch)
}
```

## Пояснення від ШІ

Вставте нижче відповідь ШІ-асистента на ваш промпт — покрокове
пояснення переплетення горутин.

Розберемо interleaving крок за кроком:

main створює WaitGroup з лічильником 1.
main запускає горутину G1.
G1 починає виконувати ch <- 42.
Оскільки канал небуферизований і ніхто зараз не читає з нього, G1 зупиняється на операції запису.
G1 не доходить до wg.Done(), бо він заблокований на ch <- 42.
main продовжує виконання і викликає wg.Wait().
wg.Wait() чекає, поки лічильник WaitGroup стане 0, але це не станеться, бо G1 ніколи не дійде до wg.Done().
У цей момент:
G1 чекає, поки хтось прочитає з каналу;
main чекає, поки G1 виконає wg.Done();
жоден із них не може продовжитися.
Отже, виникає циклічне очікування: “я чекаю на читання” ↔ “я чекаю на завершення goroutine”.
